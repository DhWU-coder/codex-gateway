# Web Chat 原子刷新设计

## 目标

刷新已登录的 Web Chat 时，浏览器继续保留旧页面，服务端准备完整首屏数据后一次性返回新页面。新页面首次绘制时已经包含用户、模型、会话列表、当前会话消息、Trace、命令和能力目录，不显示登录页、加载页或空会话壳子。

## 当前问题

`GET /chat` 只根据 Cookie 决定登录页和 Chat 外壳的可见状态。页面脚本启动后仍需依次请求 `/api/chat/me`、`/api/chat/models`、`/api/chat/sessions`、当前 Session 和能力目录。浏览器提交新文档后，这些请求尚未完成，因此会看到空白外壳逐步填充。

## 方案

### 服务端 Bootstrap

已登录的 `GET /chat` 在发送 HTML 前完成以下工作：

1. 校验 Cookie 并取得用户与 CSRF Token。
2. 读取模型目录和会话列表。
3. 没有会话时创建默认会话，保持现有首次进入行为。
4. 读取最新会话的消息、Trace 和能力目录。
5. 将结果作为版本化 JSON Bootstrap 数据安全内嵌到 HTML。

未登录请求不构建 Bootstrap，直接返回登录页。

### 首次绘制

带 Bootstrap 的页面在 `<html>` 上设置待恢复标记，CSS 暂时禁止新文档绘制。页面脚本同步解析内嵌 JSON、恢复状态并完成 DOM 渲染，然后移除标记。所有操作发生在同一个同步任务内，因此浏览器首次绘制就是完整会话页。

### 后续行为

- 登录、注册、切换会话及实时事件继续使用现有 API。
- 没有内嵌 Bootstrap 时保留原有异步恢复流程，作为兼容和故障降级路径。
- Cookie 在返回页面后失效时，任意 API 的 `401` 仍统一清理状态并显示登录页。

## 安全

- Bootstrap JSON 中的 `<`、`>`、`&` 和 Unicode 行分隔符必须转义，避免 `</script>` 提前结束 JSON Script。
- 不内嵌 Session Token，只使用现有前端已经可读取的用户、CSRF Token 和公开会话数据。
- 能力目录继续使用公开投影，不暴露本地绝对路径或内部工具参数。

## 验证

- HTTP 测试验证已登录 `/chat` 会等待 Bootstrap 完成并内嵌完整数据。
- 页面测试验证恶意文本不能逃逸 JSON Script。
- 页面测试验证前端优先同步恢复 Bootstrap，且异步恢复路径仍存在。
- 完整单元测试、类型检查、构建和真实浏览器刷新验证全部通过。
