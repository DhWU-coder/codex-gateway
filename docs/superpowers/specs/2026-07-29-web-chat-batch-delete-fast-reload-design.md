# Web Chat 批量删除与 Fast 热更新设计

## 背景

Web Chat 左侧会话列表目前只支持逐条删除。用户需要进入选择模式，勾选任意会话或全选后一次删除；运行中的会话也必须先停止再删除。

全局配置已经写入 `codex.fast: false`，但配置热更新只更新飞书 Channel，没有更新 `WebChatManager` 持有的 Codex 配置快照。结果是配置保存后创建的 Web Chat 会话仍可能使用旧的 Fast 默认值。Chat 页面显示的是会话实际保存值，因此显示本身正确，错误发生在新会话默认值的来源。

## 目标

1. 左侧会话栏支持选择、全选、取消和批量删除。
2. 运行中的会话可以删除，删除前必须先停止执行。
3. 批量删除只确认一次，并显示已选数量及运行中数量。
4. 配置热更新后，新 Web Chat 会话使用最新模型、Effort、Fast 和 Verbosity 默认值。
5. 没有消息、Thread、目标或计划状态的空白会话同步最新默认值。
6. 已有内容或正在运行的会话继续保留会话级运行配置。

## 非目标

- 不增加会话筛选、搜索或分页。
- 不改变飞书会话运行参数的继承规则。
- 不为批量删除提供撤销或回收站。
- 不把已有内容会话的运行参数强制改成全局配置。

## 交互设计

### 选择模式

“新对话”按钮下方增加一个紧凑的会话操作栏。正常状态只显示“选择”；进入选择模式后显示：

- “全选”复选框；
- “已选 N 项”状态；
- “删除”按钮；
- “取消”按钮。

每条会话左侧显示复选框。选择模式下点击会话行只切换勾选，不打开会话；退出选择模式后恢复原有打开、右键、长按和省略号菜单行为。

“全选”选择当前账户下的全部会话，包括正在运行的会话。部分选中时复选框显示不确定状态。没有选中项时删除按钮禁用。

### 删除确认与结果

点击批量删除时只显示一次浏览器确认：

`确定删除已选择的 N 个会话？其中 M 个正在运行，将先停止任务。`

没有运行中会话时不显示第二句。确认后锁定选择控件，防止重复请求。

后端返回删除、停止和失败项目。全部成功时退出选择模式；部分失败时保留失败项目的选择状态并显示错误提示。

如果当前会话被删除，前端打开剩余会话的第一条；如果没有剩余会话，则创建新的空白会话。

## 后端设计

### Manager

`WebChatManager` 增加批量删除能力，输入用户 ID 和去重后的会话 ID 列表，逐项执行：

1. 验证会话属于当前用户。
2. 如果会话正在运行或仍有 Router，调用现有停止逻辑。
3. 删除本地会话、历史、Trace、Router 和运行状态。
4. 异步删除对应 App Server Thread。
5. 发布 `session.deleted` 事件。

返回结构包含：

- `deletedIds`：成功删除的会话 ID；
- `stoppedIds`：删除前被停止的会话 ID；
- `failed`：包含会话 ID 和错误信息的失败项。

现有单会话删除复用同一停止后删除逻辑，确保所有入口行为一致。

### HTTP

新增 `DELETE /api/chat/sessions`，请求体为：

```json
{
  "sessionIds": ["chat-a", "chat-b"]
}
```

接口沿用现有登录、CSRF 和用户所有权校验。空数组返回参数错误；跨用户或不存在的会话作为失败项返回，不影响其他有效会话删除。

### Codex 默认配置热更新

`WebChatManager` 不再只依赖构造时的 Codex 配置快照，而是保存可更新的当前默认配置。`ChannelManager.reloadConfig()` 每次配置热更新时将最新 `config.codex` 传入 Web Chat Manager。

更新默认值时：

- 新会话通过最新 Codex 配置和 Web Chat 用户覆盖值解析运行参数；
- 空白且未运行的会话同步最新默认值；
- 用户级明确覆盖仍优先于全局配置；
- 有消息、Thread、目标、计划或权限状态的会话不修改；
- 已创建 Router 的会话不修改。

## 错误处理

- 批量删除中的单项失败不会回滚已经成功删除的会话。
- 删除运行会话时，即使停止函数报告没有活动任务，也继续清理会话持久化数据。
- 配置热更新失败继续进入现有配置重载错误状态，并记录 Web Chat 更新错误。
- 前端请求失败时保留当前选择，解除按钮锁定并显示错误。

## 测试

1. Manager 测试运行会话批量删除会先触发停止，并清理会话。
2. Manager 测试批量删除去重、跨用户失败和部分成功。
3. HTTP 测试批量删除需要 CSRF，并返回删除、停止和失败结果。
4. ChannelManager 测试 Codex Fast 从 `true` 热更新为 `false` 后，新会话使用 `false`。
5. Manager 测试空白会话同步最新默认值，有内容会话保持旧值。
6. 页面测试选择、全选、计数、一次确认、按钮禁用和移动端样式标记。
7. 运行完整测试、类型检查、构建和真实浏览器桌面/移动端检查。
