# Web Chat 账户设置设计

## 目标

将 Web Chat 左下角的“账户”入口改为“设置”。设置弹窗同时提供账户默认模型配置和修改密码能力，且两类设置使用独立表单和提交动作。

## 用户体验

设置弹窗包含两个标签页：

1. “模型配置”是默认标签页。
2. “修改密码”保留当前密码和新密码字段。

模型配置包含：

- 默认模型：支持直接输入模型 ID，也支持从模型目录下拉选择。
- 默认推理强度：根据当前选择或继承后实际生效的模型动态列出。
- 默认速度：支持继承全局、标准和 Fast。
- 每一项都支持“继承全局”，并显示当前实际继承值。
- 不展示或修改 Verbosity。

模型配置保存成功后不退出登录。修改密码成功后撤销当前登录并返回登录页。

## 数据与继承规则

账户记录继续使用已有的可选字段：

- `model`
- `reasoningEffort`
- `fast`

字段为空表示继承全局 Codex 配置。接口同时返回账户显式值与当前实际生效值，前端据此展示“继承全局（当前：具体值）”。

账户默认值更新后：

- 新会话使用最新账户默认值。
- 没有消息、Thread、Goal、Plan、权限覆盖和运行任务的空白会话立即同步。
- 已有内容或上下文状态的会话保留原来的模型参数。

## 接口

新增登录用户专用接口：

- `GET /api/chat/account-settings`
  - 返回当前账户的显式默认值和实际生效值。
- `PUT /api/chat/account-settings`
  - 需要有效登录和 CSRF Token。
  - 只允许修改 `model`、`reasoningEffort` 和 `fast`。
  - `null` 表示继承全局。
  - 返回更新后的账户公开信息、显式默认值和实际生效值。

现有 `POST /api/chat/auth/password` 保持不变。

## 服务端校验

保存账户默认值前读取共享模型目录：

- 显式模型必须存在于当前模型目录。
- 实际生效的 Effort 必须受实际生效模型支持。
- 实际生效的 Fast 为开启时，模型必须支持 Fast。
- 非法请求返回明确的 `400` 错误，不写入部分配置。

更新成功后，通过现有 Session 事件通知空白会话变化。

## 前端结构

保留现有 Dialog 机制，将单一密码表单改成设置容器：

- Dialog 标题和关闭按钮。
- “模型配置 / 修改密码”标签页。
- 模型配置独立表单。
- 修改密码独立表单。

默认模型使用带 `datalist` 的输入框，兼顾自由输入和下拉选择；Effort 与速度使用原生 `select`。保存模型配置后刷新账户信息、会话列表和当前空白会话。

## 错误处理

- 模型配置错误显示在模型配置表单内，不关闭弹窗。
- 密码错误显示在密码表单内。
- 切换标签页不清空另一页尚未提交的输入。
- 请求期间禁用对应表单的保存按钮，避免重复提交。

## 测试

- Manager：验证模型目录校验、账户默认值持久化、空白会话同步和已有内容会话保留。
- HTTP：验证读取、CSRF、防跨账户修改、保存和错误响应。
- Page：验证“设置”入口、两个标签页、三个默认配置控件、继承提示和脚本语法。
- 全量运行 `bun test`、`bun run typecheck`、`bun run build` 和 `git diff --check`。
