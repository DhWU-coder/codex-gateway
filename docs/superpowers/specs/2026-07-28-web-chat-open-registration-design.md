# Web Chat 开放注册设计

## 目标

在现有 `/chat` 登录页增加开放注册能力。任何能够访问 Chat 路由的局域网用户都可以创建账号，注册成功后自动登录；本机管理员仍可在 Web Chat 频道中停用、重置密码、普通删除或彻底删除用户。

## 配置

根配置增加：

```yaml
webChat:
  registrationEnabled: true
```

默认值为 `false`，避免升级后意外开放注册。当前项目配置显式设为 `true`。配置热更新后，新请求立即使用新值；关闭时页面不显示注册入口，注册 API 也返回 `403`。

## 注册接口

新增公开 Chat 路由：

```text
POST /api/chat/auth/register
```

请求体：

```json
{
  "username": "alice",
  "password": "password-123"
}
```

注册接口只接受用户名和密码，不允许客户端指定启用状态、模型、Effort、Fast、Verbosity、工作目录或用户 ID。新用户默认启用，运行参数全部留空并继承全局配置，目录继续由不可变用户 ID 推导。

注册成功返回与登录相同的公开用户、CSRF Token、过期时间和 `HttpOnly; SameSite=Strict` Session Cookie，浏览器直接进入 Chat。

错误状态：

- 注册关闭：`403`；
- 用户名或密码不合法：`400`；
- 用户名已存在：`409`；
- 同一真实客户端 IP 请求过于频繁：`429`，包含 `Retry-After`；
- 其他用户存储错误：`400`，不返回密码哈希或内部路径之外的敏感数据。

## 限流

注册限流按 Web Server 从 socket 读取的真实客户端地址计算，不读取 `X-Forwarded-For`。每个地址一小时最多发起 5 次注册请求，成功、重复用户名和校验失败都计数，防止用无效请求绕过限制。窗口过期后自动恢复。

登录限流保持现状，不与注册限流共用计数。

## 页面

注册开启时，认证卡片显示“登录 / 注册”两个标签：

- 登录表单保持用户名和密码；
- 注册表单包含用户名、密码、确认密码；
- 前端先校验两次密码一致，再提交注册 API；
- 注册成功复用登录后的身份接受和初始化流程；
- 注册失败在注册表单内显示服务端错误；
- 切换表单不会自动提交，也不会把密码复制到另一表单。

注册关闭时只渲染现有登录表单，不显示注册标签或注册表单。Chat 页面仍不包含管理 API、完整工具日志或管理入口。

## 服务数据流

1. Web Server 根据当前配置判断是否开放注册。
2. 注册 API 在认证前处理，并使用真实 socket 地址执行注册限流。
3. `WebChatAuthService` 校验限流，调用现有 `WebChatUserStore.create`。
4. 用户存储继续执行用户名规范化、唯一性检查、Argon2id 哈希、原子 JSON 写入和目录创建。
5. 认证服务为新用户签发与登录一致的 Session 和 CSRF Token。
6. 页面接受身份并加载模型和 Session；没有 Session 时创建首个空 Session。

## 测试

- 配置默认关闭、显式开启，并可在 Daemon 热更新后影响注册判断；
- 注册成功后密码不落明文、用户默认启用、运行参数为空并可直接认证；
- 重复用户名、非法输入和每 IP 一小时 5 次限流；
- 注册关闭时 API 返回 `403`，开启时返回 Cookie 和 CSRF；
- 注册页面只在开启时渲染，脚本语法有效，确认密码不一致时不发请求；
- 远程管理 API 仍返回 `403`，伪造转发头不影响限流或管理边界；
- 全量测试、类型检查、构建和真实局域网注册流程。
